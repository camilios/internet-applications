# مطابقة نص المتطلب الرابع

هذه المراجعة تعتمد النص العربي الذي قدّمه المستخدم بعد التنفيذ الأول. اختير البريد الوهمي في الاختبارات الأولى، ثم طلب المستخدم تفعيل Resend. **الإعداد المحلي الحالي يرسل عبر Resend SMTP الحقيقي مع تعطيل المحاكاة.** نجح اختبار الطلب 300016 مع إيقاف العامل وتشغيله، وأكّد المستخدم وصول رسالة التأكيد إلى بريده. [إعداد Resend والدليل](resend-setup.md).

| بند النص | التنفيذ |
| --- | --- |
| إنشاء الطلب دون انتظار البريد | يحفظ Laravel الطلب وحدث Outbox في معاملة واحدة؛ ينشره `outbox:publish` إلى RabbitMQ في عملية مستقلة. لا ينتظر طلب HTTP إرسال البريد أو توافر العامل. |
| عامل بريد مستقل | `orders:email-worker` عملية منفصلة تستخدم Laravel Mail وResend SMTP حالياً مع `ORDER_EMAIL_ALLOW_MOCK=false`. يُسجّل قبول النقل بوصفه `external`؛ وأكّد المستلم وصول رسالة الطلب 300016. تبقى السجلات التاريخية الوهمية بوضع `mock`. |
| عدم ضياع الرسائل | Outbox محفوظ حتى تأكيد الناشر، ورسائل وطوابير دائمة، وإقرار يدوي بعد النجاح أو بعد تأكيد النقل إلى طابور المحاولة/DLQ. فشل النقل لا يؤكد الرسالة الأصلية. |
| إعادة المحاولة وDLQ | محاولات محدودة، تأخير متزايد، وطابور مستقل للرسائل غير القابلة للمعالجة أو المستنفدة للمحاولات. |
| تحديث صفحة الزبون | قناة خاصة `orders.{id}` للطلب المفتوح وللطلبات المملوكة الظاهرة في قائمة الزبون؛ تُحدَّث القائمة وتفاصيل الطلب المعني من REST دون إعادة تحميل الصفحة، مع إشعار عربي برقم الطلب وحالته الجديدة عند وصول حدث فعلي. لا تغيير لبنية CRUD أو مفاتيح الاستعلامات. |
| ظهور الطلب للمسؤول | قائمة الطلبات تتحدث لحظياً؛ إشعار عربي برقم الطلب يظهر للمسؤول حتى وهو في صفحة الإحصاءات. إعادة الاتصال تعيد جلب البيانات دون توليد إشعارات طلبات مكررة. |
| صلاحية القنوات | JWT قبل الاشتراك؛ `admin.orders` للمسؤول، و`orders.{id}` لمالك الطلب فقط. REST محمي بصورة مستقلة. |

## حدود وضع البريد الوهمي

- البريد الوهمي لا يصل إلى صندوق بريد خارجي، ولا يُقدّم بوصفه إثباتاً لذلك.
- العامل يتحقق من إعداد البريد قبل استهلاك أي رسالة. إعداد غير صالح لا يسحب الرسائل ولا يستهلك محاولاتها.
- وضع `log` أو `array` يتطلب تفعيل المحاكاة صراحةً في البيئة المحلية/الاختبارية؛ لا تسمح بيئة الإنتاج بمحاكاة التسليم. تستخدم اختبارات Laravel ناقل `array` في بيئة `testing`.
- الطوابير المركبة التي يمكنها الرجوع إلى سجل محلي لا تُقبل بوصفها إرسالاً خارجياً.
- الحقل الجديد `notification_deliveries.delivery_mode` يميز `mock` عن `external`. السجلات القديمة تبقى بلا تصنيف بدلاً من افتراض إرسال حقيقي. تبديل المزوّد لا يعيد إرسال البريد السابق تلقائياً.
- يلزم تطبيق ترحيل `2026_11_14_000003_add_delivery_mode_to_notification_deliveries.php` مع الترحيلين السابقين.

## الإثبات المطلوب

إثبات WebSocket فعلي واختبارات React السابقة موجودان في [تقرير QA](req4-qa-report.md). تُسجّل فيه نتائج إعادة التحقق بعد تصحيح المحاكاة وإضافة إشعار لوحة المسؤول، مع التمييز بين اختبار المتصفح الفعلي، واختبار بروتوكول WebSocket، واختبارات الناقل الوهمي.

نجح اختبار المتصفح الفعلي على الواجهة المبنية للإنتاج: إشعار الطلب وعدد الطلبات وقائمة المسؤول، ثم موافقة المسؤول عبر عنصر الواجهة الموجود وتغيّر صفحة الزبون إلى «مؤكد». تحقّق الاختبار من بقاء توقيت بدء المستندات الأربعة ثابتاً، أي لم تُعد تحميل الصفحات. يستخدم الاختبار HTTP وJWT وEcho وReverb وطابور البث الحقيقي، مع محاكاة حدود المخزون فقط.

صور الدليل: [إشعار لوحة المسؤول](req4-evidence/dashboard-new-order.png)، [موافقة المسؤول](req4-evidence/admin-approved.png)، [حالة الزبون بعد الموافقة](req4-evidence/customer-confirmed.png). الصور تعرض النتيجة المرئية؛ اختبار المتصفح نفسه يتحقق من عدم إعادة تحميل الصفحات.

[نتيجة التشغيل المحفوظة](req4-evidence/browser-result.json) و[مصدر اختبار المتصفح](../frontend/tests/realtime/browser-acceptance.mjs) متاحان للمراجعة وإعادة التشغيل.

أثناء تشغيل المشروع لاختبار Postman، أصبح RabbitMQ 3.13 متاحاً محلياً ونجح إثبات إيقاف عامل البريد وتشغيله على المنظومة الفعلية: بقيت رسالة واحدة في الوسيط، مع حدث منشور وصفر سجلات تسليم أثناء التوقف؛ بعد التشغيل أصبحت معالجة `mock` واحدة والطابور فارغاً. نجح أيضاً إنشاء الطلب عبر gRPC الحقيقي وقاعدة MySQL، ووصول حدث الطلب للمسؤول وتحديث الحالة للمالك عبر Reverb. [نتيجة التشغيل الفعلية](req4-evidence/postman-runtime.json).

نفّذ هذا التحقق التاريخي وكيل التنسيق عبر Node/Chai باستخدام طلبات مجموعة Postman وسكربتاتها؛ لم يُشغّل تطبيق Postman أو Newman. نجح 28 طلب HTTP و32 تحققاً من السكربتات. اختبار Resend اللاحق أضاف إثبات البريد الخارجي، لكنه لا يحوّل اختبارات النقل الأربعة المعزولة أو تزامن مستهلكي MySQL إلى اختبارات ناجحة.

في اختبار Resend اللاحق: عاد إنشاء الطلب 300016 بنجاح والعامل متوقف، وبقيت رسالة واحدة في RabbitMQ وصفر تسليمات. بعد التشغيل أصبحت معالجة `external` واحدة والطابور فارغاً. لم يضف تكرار الطلب/الحدث سجلاً آخر، وأكّد المستخدم وصول البريد. المرسل التجريبي `onboarding@resend.dev` مقيّد ببريد صاحب حساب Resend إلى أن يُوثَّق نطاق مملوك. [الدليل المحفوظ](req4-evidence/resend-external-email.json) و[أوامر التشغيل والقبول](req4-operations.md).

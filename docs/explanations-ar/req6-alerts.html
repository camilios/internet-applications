١. من المقياس إلى إشعار وصل فعلاً

يقرأ Prometheus عدد رسائل البريد الجاهزة من RabbitMQ وعدّادات ردود HTTP من مجمّع Nginx. تقيّم Grafana قاعدتين على تلك البيانات. إذا بقي الشرط متحققاً خلال فترة الانتظار، ترسل Grafana إشعاراً عبر HTTP إلى http-metrics. يطبع المجمّع حدث JSON ويزيد عدّاد استقبال التنبيه. يقرأ الاختبار ذلك العدّاد من Prometheus حتى يتأكد أن الإشعار وصل.

القاعدةشرط الإطلاقكيف نجعل الشرط يحدث؟

  1. status=~"5.." يختار ردود الخادم والبوابة من فئة 5xx.
  2. increase(...[1m]) تقدّر الزيادة في كل عداد خلال دقيقة، ثم يجمع sum كل الحالات والنسخ المختارة. يطبّق البسط على 5xx، ويطبق المقام على كل ردود HTTP.
  3. clamp_min(..., 1) يبقي المقام واحداً على الأقل إذا كانت العينة موجودة لتفادي القسمة على صفر. الضرب في 100 يخرج نسبة مئوية. شرط and (... >= 3) يستخدم نتيجة المقارنة اليمنى لتصفية النتيجة اليسرى عندما يقل عدد الأخطاء؛ تنتقل قيمة النسبة إلى B عند تحقق شرط العدد.

تضبط القاعدتان for: "10s" لتمرّ القاعدة بحالة انتظار قبل الإطلاق إذا استمر تجاوز العتبة عبر التقييمات. حالة غياب العينات مضبوطة على OK، وحالة خطأ تنفيذ الاستعلام Error. يعطي severity: warning تصنيفاً للإشعار، وتشرح summary سبب التنبيه. الفرق بين فاصل التقييم ومدة الانتظار مهم، فقد يُسحب المقياس أولاً، ثم يأتي وقت التقييم، ثم وقت إرسال الإشعار. دورة تقييم التنبيه في Grafana · معاملات PromQL

افتح ops/req6/http-metrics.mjs · الأسطر 52–76

http.createServer(async (req, res) => {
  if (req.method === 'GET' && req.url === '/metrics') {
    res.writeHead(200, {'Content-Type': 'text/plain; version=0.0.4; charset=utf-8'}).end(metrics())
    return
  }
  if (req.method !== 'POST' || req.url !== '/notifications') { res.writeHead(404).end(); return }
  try {
    const parts = []
    let size = 0
    for await (const chunk of req) {
      size += chunk.length
      if (size > 65536) { res.writeHead(413).end(); return }
      parts.push(chunk)
    }
    const payload = JSON.parse(Buffer.concat(parts))
    for (const alert of payload.alerts) {
      const name = alert.labels?.alertname
      if (!alertNames.has(name) || !['firing', 'resolved'].includes(alert.status)) continue
      const labels = 'alert="' + name + '",status="' + alert.status + '"'
      notifications.set(labels, (notifications.get(labels) ?? 0) + 1)
      console.log(JSON.stringify({time: new Date().toISOString(), message: 'Alert notification', alert: name, status: alert.status}))
    }
    res.writeHead(200).end()
  } catch { res.writeHead(400).end() }
}).listen(9108)

GET /metrics يبقى مسار قراءة Prometheus. يطابق الفرع الثاني POST /notifications ويحصر حجم الجسم في 65536 بايت، ثم يحلل JSON ويمر على مصفوفة alerts. يأخذ alertname وحالة كل تنبيه مسموح. تزيد Map زوج الاسم والحالة ويكتب المجمّع سطر JSON. يرد 200 بعد الاستلام والمعالجة. تخرج القيم المحسوبة باسم order_alert_notifications_total من الدالة metrics، ولذلك يستطيع الاختبار الرجوع إلى المقياس نفسه والتأكد أن الاستلام حدث في هذه الجولة.

افتح ops/req6/http-metrics.mjs · الأسطر 26–41

function metrics() {
  const lines = ['# TYPE order_http_requests_total counter', '# TYPE order_http_duration_seconds histogram',
    '# TYPE order_alert_notifications_total counter']
  for (const [replica, stats] of replicas) {
    const labels = 'replica="' + replica + '"'
    for (const [status, count] of stats.codes) {
      lines.push('order_http_requests_total{' + labels + ',status="' + status + '"} ' + count)
    }
    buckets.forEach((bound, i) => lines.push('order_http_duration_seconds_bucket{' + labels + ',le="' + bound + '"} ' + stats.buckets[i]))
    lines.push('order_http_duration_seconds_bucket{' + labels + ',le="+Inf"} ' + stats.count,
      'order_http_duration_seconds_count{' + labels + '} ' + stats.count,
      'order_http_duration_seconds_sum{' + labels + '} ' + stats.sum)
  }
  for (const [labels, count] of notifications) lines.push('order_alert_notifications_total{' + labels + '} ' + count)
  return lines.join('\n') + '\n'
}

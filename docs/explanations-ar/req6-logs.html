١. رحلة معرّف التتبع

يصل طلب الشراء إلى Laravel مع X-Correlation-ID. يحتفظ Laravel بالقيمة مع الطلب، ويمرّرها إلى المستودع في gRPC metadata. عند حفظ الطلب تُخزَّن القيمة في حمولة Outbox. ينشرها العامل الناشر إلى RabbitMQ، ثم يأخذها عامل البريد من الرسالة نفسها. بهذه الطريقة تبقى القيمة موجودة حتى إذا أُوقف عامل البريد وعاد بعد انتهاء طلب HTTP.

<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Log;
use Illuminate\Support\Str;
use Symfony\Component\HttpFoundation\Response;

class TraceRequest
{
    public function handle(Request $request, Closure $next): Response
    {
        $incoming = $request->header('X-Correlation-ID');
        $id = is_string($incoming) && Str::isUuid($incoming) ? strtolower($incoming) : (string) Str::uuid();
        $request->attributes->set('correlation_id', $id);
        $observed = config('logging.default') === 'observability';
        if ($observed) {
            Log::info('HTTP request started', ['correlation_id' => $id]);
        }
        $response = $next($request);
        $response->headers->set('X-Correlation-ID', $id);
        if ($observed) {
            Log::info('HTTP request finished', ['correlation_id' => $id, 'status' => $response->getStatusCode()]);
        }

        return $response;
    }
}

أسئلة الأستاذ

جاوب بصوت عالٍ وحدّد السطر الذي تستند إليه، ثم افتح الإجابة وقارنها بجوابك.

متوسط 1. ما الفرق بين Correlation ID وEvent ID ورقم الطلب؟

افتح الإجابة بعد محاولتك

الأول يمتد من HTTP إلى الخطوات المرتبطة به، والثاني يعرّف رسالة Outbox ومعالجتها، والثالث هو هوية الطلب في البيانات والواجهة.

متوسط 2. أين يولد Laravel معرّفاً ويمرره؟

افتح الإجابة بعد محاولتك

TraceRequest يقرأ الترويسة ويفحص UUID أو يولد واحداً ثم يحفظه في attributes ويعيده في الرد.

متوسط 3. ليش لازم نضعه في الحمولة عند إنشاء Outbox؟

افتح الإجابة بعد محاولتك

ناشر Outbox وعامل الرسالة يعملان بعد انتهاء HTTP وفي عمليات أخرى. تخزين القيمة ضمن الحمولة يجعلها متاحة لهما.

صعب 4. إذا وصلت قيمة `private-value` في الترويسة، تتبع ما يصير.

افتح الإجابة بعد محاولتك

يفشل فحص UUID في الوسيط، فيولد UUID جديداً. هذا UUID يعاد في الرد ويمر عبر metadata والحمولة، وتُكتب القيمة الجديدة في حقول السجل المسموحة.

صعب 5. أفرجيني مكان الاعتماد على نفس التتبع عند PHP وTypeScript دون تعديل protobuf.

افتح الإجابة بعد محاولتك

InventoryGrpcClient يضع x-correlation-id في metadata، وينقلها InventoryGrpcStub إلى نداء gRPC. handlers.ts يقرأ أول قيمة منها في الغلاف قبل كتابة نتيجة العملية.

صعب 6. الجسم فيه Correlation ID ولكن log في المستودع فيه قيمة مختلفة. أين تبحث؟

افتح الإجابة بعد محاولتك

طابق ترويسة HTTP والـattributes، وتأكد أن Stub تلقى metadata وأرسلها باسم lowercase، وأن القيمة التي قرأها wrapper اجتازت نمط UUID.

صعب 7. لو أُعيد تسليم الحدث بعد تعطل الناشر، ما الذي يبقى ثابتاً؟ وما الذي قد يزيد؟

افتح الإجابة بعد محاولتك

UUID الحدث والتتبع ورقم الطلب تبقى من جسم الرسالة نفسه. رقم المحاولة قد يزيد عبر مسار retry. يتحقق المرسل من سجل تسليم فريد للحدث قبل إعادة إرسال البريد.

صعب 8. هل ACK وحده دليل أن البريد وصل للصندوق؟

افتح الإجابة بعد محاولتك

ACK يعني أن الوسيط يستطيع اعتبار رسالة العمل منتهية، وقد يحدث بعد نشرها إلى retry أو DLQ. الإثبات الأخير في الجولة يفحص قبول الناقل ثم يعد رسالة مطابقة في Mailpit.

صعب 9. كيف تمنع سطر قديم أو طلباً آخر من اختلاط رحلة العميل؟

افتح الإجابة بعد محاولتك

يقرأ verify.py خرج الحاويات من وقت بدء الجولة، يفك JSON ويطابق حقل correlation_id، ثم يقارن event_id وorder_id عبر الناشر والعامل.

صعب 10. إذا وصل رسالة قديمة بلا correlation_id، هل تظهر نفس رحلة HTTP؟

افتح الإجابة بعد محاولتك

يستعمل الناشر والمعالج UUID الحدث للربط في الخلفية. استعادة رحلة HTTP القديمة تحتاج معرّفها الأصلي الذي لم يُحفظ في الحدث.

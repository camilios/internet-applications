تحسين قاعدة البيانات

ابدأ بالاستعلام المكلف، ثم خطة التنفيذ، ثم التعديل المناسب. لا تبدأ بإضافة فهارس إلى كل عمود.

1.1 كيف نعرف أي الاستعلامات بطيء؟

زمن HTTP ليس زمن SQL وحده. طلب عرض المنتج قد يقضي وقتًا في توثيق المستخدم، وتحديد مصدر القراءة، وجلب العلاقات، وgRPC، وبناء JSON ثم نقله. لذلك نراقب الاستعلامات نفسها ونربطها بمسار محدد؛ لا نستنتج أن قاعدة البيانات هي السبب من بطء الصفحة فقط.

في الدليل التاريخي كان استعلام آخر الطلبات مع فلتر status = 'shipped' يمسح 300,004 صفوف ويحتاج 303 ms في اللقطة المسجلة. وكان عرض آخر الطلبات بلا فلتر يستغرق 333 ms. هذان مرشحان واضحان للفحص لأننا نطلب 15 صفًا فقط بينما نقرأ جدولًا كبيرًا ثم نفرزه.

أداة الفحص الحالية تنفّذ استعلامات محددة، وتحتفظ بمعاملاتها، وأعداد الصفوف، والفهارس والخطط. البيانات لم تُصفّر لإعادة الاختبار؛ بقيت 300,004 طلبات و749,372 بنود.

1.2 الفرق بين EXPLAIN وEXPLAIN ANALYZE

EXPLAIN يعرض خطة المحسّن وتقديراته. أما EXPLAIN ANALYZE فينفّذ الاستعلام ويضيف أزمنة فعلية وعدد الصفوف والتكرارات. لهذا نستخدمه هنا مع استعلامات قراءة مقصودة، ثم نحتفظ بالمخرجات بدل الاكتفاء بعبارة «أصبح أسرع».

مثال تعليمي لنفس شكل الاستعلام المستخدم في القياس

EXPLAIN ANALYZE
SELECT * FROM orders
WHERE status = 'shipped'
ORDER BY created_at DESC
LIMIT 15;
  • key: الفهرس الذي اختير فعلًا، وليس كل فهرس موجود في الجدول.
  • rows في EXPLAIN تقدير. أما actual ... rows=... loops=... فهو عمل حدث أثناء التنفيذ.
  • الأرقام في actual time=a..b تمثل زمن أول وآخر صف لكل تكرار بالعقدة؛ راقب أيضًا loops ولا تجمع أزمنة العقد جمعًا مباشرًا، لأنها متداخلة.
  • ابحث عن مسح عدد كبير، أو فرز لا نحتاجه، أو تكرار قراءة علاقة لكل صف. قراءة LIMIT 15 من فهرس مناسب تختلف عن مسح الجدول وفرزه ثم أخذ أول 15.

2.1 Primary وReplica: مسؤوليتان مختلفتان

الـPrimary هو وجهة الكتابة، والـReplica يطبّق تغييرات المصدر ويُستخدم لتوزيع قراءات التطبيق. النسخ غير المتزامن يعني أن نجاح الكتابة على المصدر لا يضمن أن النسخة طبّقتها في اللحظة نفسها.

Laravelقراءة / كتابة
⇄
Primary · server 1كل الكتابات ومصدر الحقيقة
←
Replica · server 2قراءات بعد التحقق من اللحاق

خدمة المخزون ليست نسخة من قاعدة Laravel؛ لها قاعدة مستقلة ومالك مختلف للبيانات. لا نستخدم Replica الكتالوج بديلًا عن سؤال خدمة المخزون عن كمية متاحة الآن.

namespace App\Services;

use Illuminate\Database\Connection;

class ReadReplicaRouter
{
    public function route(Connection $connection, bool $recentWrite = false): string
    {
        $connection->useWriteConnectionWhenReading(false);
        if ($recentWrite || $connection->transactionLevel() > 0) {
            $connection->useWriteConnectionWhenReading();
            return 'primary';
        }

        try {
            // A lightweight primary fence also protects anonymous product reads and evicted markers.
            // sticky alone only protects reads within the same request.
            $position = $connection->selectFromWriteConnection('SELECT @@GLOBAL.gtid_executed AS position');
            $gtid = (string) ($position[0]->position ?? '');
            if ($gtid === '') {
                throw new \RuntimeException('A primary GTID fence is required.');
            }
            $statement = $connection->getReadPdo()->prepare('SELECT GTID_SUBSET(?, @@GLOBAL.gtid_executed)');
            $statement->execute([$gtid]);
            if ((string) $statement->fetchColumn() !== '1') {
                throw new \RuntimeException('Replica has not applied the primary fence.');
            }
            return 'replica';
        } catch (\Throwable) {
            // Lag, connection errors, or unverified state must never expose an older representation.
            $connection->useWriteConnectionWhenReading();
            return 'primary';
        }
    }

ETag يقلل إعادة إرسال المحتوى غير المتغيّر، وgzip يقلل حجم المحتوى الذي يجب إرساله. لكل منهما وظيفة مستقلة.

4.1 ETag وIf-None-Match

ETag مُعرّف لتمثيل المورد. يحتفظ العميل بالقيمة ثم يرسلها في If-None-Match. إذا لم يتغير التمثيل، يعود 304 Not Modified بلا جسم. وإذا تغيّر السعر أو التصنيف أو المخزون الداخل في التمثيل، يجب أن تأتي استجابة 200 بجسم جديد ومعرّف جديد.

Accept: application/json

HTTP/1.1 200 OK
ETag: W/"current-value"

GET /api/products/1
If-None-Match: W/"current-value"

HTTP/1.1 304 Not Modified
[no response body]

<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class ConditionalGet
{
    public function handle(Request $request, Closure $next): Response
    {
        $response = $next($request);
        if ($request->isMethod('GET') && $response instanceof JsonResponse && $response->getStatusCode() === 200) {
            // Compute after rendering: the representation still includes live stock.
            // A semantic validator remains valid for both gzip and identity bytes.
            $response->setEtag(sha1($response->getContent()), true);
            $response->headers->set('Cache-Control', 'private, no-cache');
            $response->isNotModified($request);
        }

        return $response;
    }
}

4.2 لماذا أصبح ETag ضعيفًا W/ عند إضافة gzip؟

بايتات JSON العادية تختلف عن بايتات gzip، رغم تطابق المحتوى بعد الفك. لا يصح إعطاء التمثيلين معرّفًا قويًا واحدًا على أساس تطابق البايتات. اخترنا معرّفًا دلاليًا ضعيفًا W/ صالحًا لمقارنة GET الشرطية عبر التمثيلين، مع Vary: Accept-Encoding لتمييز اختيار الترميز.

الضعف هنا وصف لقواعد المقارنة، لا لسوء البيانات أو غياب الأمان. كما أن hash المستخدم لتعريف المحتوى ليس توقيعًا أمنيًا ولا بديلًا عن JWT.

  • الحد المعتاد 1,024 بايت؛ الرد الصغير أو الذي لا يستفيد من الضغط يبقى عاديًا إذا كان identity مقبولًا.
  • gzip;q=0 يمنع اختيار gzip؛ والتفضيل الصريح لـidentity يُحترم. إذا رفض العميل الترميزين المتاحين، يعود 406 برسالة JSON.
  • يضبط الرد Content-Encoding: gzip وContent-Length على حجم الجسم المضغوط، ويحافظ على Vary الموجود.
  • لا يُضغط 304 ولا يُرسل له جسم. ولا تُجمع استجابات SSE أو البث الحي داخل buffer بهدف ضغطها. الردود التي تطلب no-transform لا تُحوّل.
  • الكتابات والملفات والبث ليست ضمن هذه الطبقة؛ لا يتغير شكل JSON الذي يراه العميل بعد فك الضغط.

<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\AcceptHeader;
use Symfony\Component\HttpFoundation\Response;

class CompressJsonResponse
{
    private const MIN_BYTES = 1024;

    public function handle(Request $request, Closure $next): Response
    {
        $response = $next($request);
        // Limit compression to JSON reads; never buffer SSE or other streams.
        if (! $request->is('api/*') || ! $request->isMethod('GET') || ! $response instanceof JsonResponse) {
            return $response;
        }
        $response->setVary('Accept-Encoding', false);
        if ($response->getStatusCode() !== 200 || $response->headers->has('Content-Encoding') ||
            $response->headers->hasCacheControlDirective('no-transform')) {
            return $response;
        }

        $accepted = AcceptHeader::fromString($request->header('Accept-Encoding', ''));
        $wildcard = $accepted->get('*');
        $gzip = $accepted->get('gzip') ?? $wildcard;
        $identity = $accepted->get('identity');
        $identityAllowed = $identity ? $identity->getQuality() > 0 : ($wildcard === null || $wildcard->getQuality() > 0);
        $gzipAllowed = $gzip !== null && $gzip->getQuality() > 0 && function_exists('gzencode');
        if (! $gzipAllowed) {
            return $identityAllowed ? $response : $this->notAcceptable();
        }
        if ($identity !== null && $identity->getQuality() > $gzip->getQuality()) {
            return $response;
        }

        $content = $response->getContent();
        if (strlen($content) < self::MIN_BYTES && $identityAllowed) {
            return $response;
        }
        $compressed = gzencode($content, 6);
        if ($compressed === false) {
            return $identityAllowed ? $response : $this->notAcceptable();
        }
        if (strlen($compressed) >= strlen($content) && $identityAllowed) {
            return $response;
        }
        $response->setContent($compressed);
        $response->headers->set('Content-Encoding', 'gzip');
        $response->headers->set('Content-Length', (string) strlen($compressed));

        return $response;
    }

    private function notAcceptable(): JsonResponse
    {
        return new JsonResponse(['message' => 'No acceptable content encoding is available.'], 406,
            ['Vary' => 'Accept-Encoding']);
    }
}

6.3 ماذا حُذف من المشروع؟

اتُّبع تنظيف محافظ: حُذفت فقط ملفات Python bytecode المولّدة، مع التحقق من أن مساراتها داخل المشروع. لم تُحذف ملفات التطبيق أو اعتمادياته أو البيئة المحلية أو الأسرار أو اختبارات الواجهة أو التقارير والأدلة التاريخية؛ فهذه ملفات مرتبطة بالمشروع أو لازمة لفهم المقارنة، وليست فضلات مؤكدة.

عدد الملفات المولّدة المحذوفة: 3. أُزيل أيضًا التكرار في قواعد التجاهل وأُضيف تجاهل دائم لملفات الكاش المولّدة. القائمة الدقيقة والأسباب في docs/performance/focused-review/cleanup.json.

6.4 أسئلة مراجعة سريعة

هل كل Table Scan يعني فشلًا؟

لا. مسح 15 منتجًا قد يكون أرخص من مسار فهرس آخر. نربط القرار بحجم البيانات والخطة والقياس، لا بلون خانة في EXPLAIN.

هل sticky يحل قراءة بعد كتابة في طلب جديد؟

ليس وحده. لذلك يستعمل المشروع GTID fence وعلامة كتابة مؤقتة، مع الرجوع إلى Primary عند عدم لحاق النسخة.

هل TTL يغني عن الإبطال؟

لا إذا كنا نريد ظهور التعديل في القراءة التالية. TTL يحمي من بقاء قيمة بلا نهاية؛ والإبطال هو الذي يمنع الانتظار حتى انتهاء مدتها بعد تعديل المصدر.

لماذا لا نخزّن stock لتسريع تفاصيل المنتج؟

لأن قرار توفره يتغير مع حجوزات متزامنة وتملكه خدمة المخزون. الكاش القديم لا يصلح لمنع overselling؛ يبقى السؤال حيًا عبر gRPC.

هل 304 يلغي العمل على الخادم؟

يوفر الجسم المنقول، لكن المشروع يبني تمثيلًا حاليًا ويجلب stock قبل القرار. لا نزعم أن SQL وgRPC اختفيا.

لماذا قد يقل حجم الرد ولا يتحسن p95؟

لأن النقل جزء من الزمن، والضغط نفسه له كلفة، وقد تؤثر حالة الذاكرة وانتظار المعالجة. الأرقام المسجلة هي الحكم، ولا تكفي نسبة ضغط جيدة لاستنتاج سعة أعلى.

هل req/s في هذه التجربة هو حد قدرة النظام؟

لا. الحمل مقيد بخمسة VUs وthink time ومراحل صعود وهبوط. يلزم تصميم آخر للتشبع أو معدل وصول محدد إذا أردنا تقدير السعة.

6.5 مراجع أصلية للتوسع

الكود والأرقام في هذا الدليل من المشروع. للمفاهيم العامة راجع الوثائق الأصلية التالية:

  • MySQL: EXPLAIN وEXPLAIN ANALYZE، ودوال GTID.
  • Laravel: Cache::remember وEager Loading.
  • Redis: EXPIRE ومدة بقاء المفتاح.
  • RFC 9110: ETag، وAccept-Encoding، و304.
  • Grafana k6: المقاييس المدمجة.
